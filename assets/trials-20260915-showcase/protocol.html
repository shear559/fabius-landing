How the new demonstrations were made

This study creates each artifact from scratch in an independent headless Claude Code session. The baseline starts with no Fabius plugin. The treatment loads the pinned Fabius 3.1.0 plugin and explicitly requests the lean, engineering and relevant domain contracts. The same enriched brief, model, tools and run limit are used in both conditions.

Fixed before generation

  • Model: claude-sonnet-5, default reasoning. Two runs per task per condition; twelve generations.
  • Fresh task directory per run. User settings excluded with --setting-sources project, MCP configuration restricted, no persistent session. The init record is checked for plugin presence or absence. No inherited parent-chat instructions are used as the task brief. Filesystem limits are generation instructions, not an operating-system sandbox; some runs created their own verification scratch files under /tmp, as recorded in the traces.
  • Available tools: Read, Write, Edit, Bash, Glob, Grep and Skill. Network use, dependency installation, subagents and reading unrelated files are prohibited in the generation prompt. Local Python, Node and browser verification are available to both arms.
  • About fifteen minutes requested; a 1,500-second wall-clock cap. Up to three generators run concurrently. Elapsed time is affected by shared-machine load and is descriptive, not a controlled speed comparison.
  • Shared additional requirements: a user-controlled product demonstration and distinct feature states for the website; Board/List views and considered application states; a compact exact answer and a feasible-region diagram for mathematics.
  • The treatment is explicitly invoked with /fabius and directed to load parcus, disciplina and decor for web tasks or scientia for math. Direct contract-file reads are recorded separately from Skill calls. This tests instructed use of the rules, not autonomous discovery of the plugin.

The full functional suite was rechecked on all four app submissions in both browsers and widths. No product files were changed. Original, corrected and merged records are published separately. Two independent, blinded claude-opus-5 proof judges assess the unchanged eight-dimension rubric against the exact reference. Disagreement or missing evidence is not counted as a pass.

Supplementary inspection

After generation, a separate browser inspection exercises the new website demonstration controls and the app Board/List switch in Chromium and WebKit. Its observations and additional captures are published as supplementary-inspection.json alongside each UI run. This inspection does not change the frozen functional scores and is not an aesthetic assessment.

Review recovery

One proof-review request timed out. Only that missing review was repeated in a fresh bare session on the identical frozen proof; successful reviews and artifact generations were not repeated. Attempt record.

Limits

Two runs on one model do not establish a general quality or speed improvement. Functional check counts are not aesthetic ratings. Shared new requirements make this a new edition rather than a repeat of the original brief. Generated diagrams are submitted artifacts and are inspectable; the proof rubric and numeric oracle do not certify every rendered diagram label. Results include ties, misses and regressions. Older studies remain available separately.

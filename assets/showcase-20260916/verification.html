These three products show an iterative refinement with Fabius. The original and refined outputs received different amounts of work and were prepared in different sessions. This is an illustration of the workflow, not a controlled estimate of the plugin’s effect.

What was built

Lattice: a fictional notebook website with an original identity, a CSS product composition, three feature states, an explicit workflow demonstration, example pricing and a keyboard-operable mobile menu.

Fieldnote: a task workspace with Board and List views, project navigation, create/edit/delete, undo, search, compound filters, schema-validated import, export, recovery and stale-tab protection.

Mathematics: one parametric quadratic problem, presented through an interactive feasible region, objective contours, six optimizer regimes, live KKT residuals, an exact proof and an executable solver.

How the refinement was made

The owner requested a polished illustration as well as real tests. A Codex session applied the installed Fabius 3.1.0 router, lean core, design, engineering and project-memory guidance, then iterated on the artifacts using browser and numerical evidence. The site is newly authored. The app starts from the original run 06 Fabius implementation and receives a new interface plus targeted robustness fixes. The mathematical solution is a worked refinement with the prior reference answer available.

“Initial output” always shows the first baseline submission for each task from September 15: run 01 for the website, run 05 for the app and run 09 for mathematics. The original executable source and submitted diagram remain unchanged. The mathematics reading wrapper typesets the original prose, including its mistakes; it does not correct that submission.

The September 15 experiment used fresh claude-sonnet-5 sessions with matched briefs and limits. This later showcase uses Codex, additional design and verification work, existing artifacts and reference access. Model, context and effort therefore differ. No blinded proof judge was rerun for the new math proof. For causal comparison, inspect the preserved paired study with all twelve submissions, ties and misses.

Failures and evaluator correction

The first website pass failed four executions of the primary-action check because a decorative arrow entered the link’s accessible name. Marking that arrow as decorative fixed the real accessibility mismatch; the complete suite was rerun.

The old app evaluator failed four recovery scenarios because it clicked the background reset trigger instead of the confirmation inside the open dialog. The correction already existed in the September 15 study: scope the click to the active dialog and accept equivalent accessible wording. This showcase uses that previously corrected evaluator, without relaxing the recovery requirement. Both raw runs are retained below.

The first integration pass exposed a genuine font CORS mismatch in opaque-origin previews, now fixed with public-font response headers. It also exposed two harness issues: injected service-worker blocking in sandboxed contexts and an Escape assertion that ran before its asynchronous message arrived. The final run uses no injected blocker and waits for the close event. First integration receipt · final receipt: 279/279 checks. A focused final pass after sizing the app filters and packaging downloads passed 43/43 checks.

Preview and source boundaries

Embedded products run in an opaque-origin sandbox. The app preview uses isolated in-memory storage, so changes reset when it is reopened. “Expand” creates a fresh preview. Downloaded index.html builds use normal local storage when served from a local HTTP origin. The preview storage shim and guided walkthrough bridge are excluded from standalone source ZIPs. The proof’s back link points to the standalone index in its ZIP and to the isolated preview on the website. All artwork is HTML, CSS and SVG; no generated screenshot is used in place of a functioning product.

Rubik is self-hosted in its original variable WOFF2 form, with Hebrew and Latin coverage checked. The font’s OFL and the math renderer’s MIT licence are included. All previous study artifacts and source records are retained unchanged.

Published receipts replace machine-specific workspace paths with placeholders. Scores, observations and timestamps are retained. The original execution records remain in the local verification workspace.

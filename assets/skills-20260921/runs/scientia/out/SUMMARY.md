# Summary

## What was produced

- **`out/analysis.py`** — end-to-end, self-contained differential expression
  pipeline (numpy + scipy + stdlib only, no matplotlib/pandas/statsmodels).
  Reads `../counts.csv` and `../metadata.csv`, does median-of-ratios
  normalization, filters low-count genes, fits a per-gene OLS model
  (`log2(count+1) ~ intercept + condition + sequencing_run`), t-tests the
  condition coefficient (df=3), applies Benjamini-Hochberg FDR control, and
  writes `results.csv` + `volcano.svg`. Deterministic — no RNG, so every
  rerun reproduces byte-identical output.
- **`out/results.csv`** — 1968 genes (32 of 2000 dropped for being too
  sparse: mean normalized count < 5), columns
  `gene, mean_expression, log2_fold_change, p_value, adjusted_p_value, called`,
  sorted by p-value.
- **`out/volcano.svg`** — hand-rolled SVG scatter (log2FC vs −log10 p),
  significance line at padj = 0.05, top nominal hits labeled. No plotting
  library used, per the task's "numpy and scipy only" constraint.
- **`out/REPORT.md`** — competing hypotheses (true effect / pure noise /
  batch confounding / low-count artifact), method, results, which hypothesis
  the data support, and an explicit "can/cannot support" section.

3. **Schema and row-count check** on `results.csv`:
   `1968` data rows, header exactly
   `gene, mean_expression, log2_fold_change, p_value, adjusted_p_value, called`
   (1968 genes tested + 1 header = 1969 lines total, matches `wc -l`).

4. **SVG well-formedness**: parsed `out/volcano.svg` with
   `xml.etree.ElementTree` — parses without error.

5. **Design sanity check**: verified the condition/batch design matrix is
   full rank (`sequencing_run` is correlated with but not identical to
   `condition` — ctrl runs A,A,B vs treated runs A,B,B), so the OLS fit for
   the batch-adjusted model is well-posed (confirmed by inspecting the
   printed design matrix and that `np.linalg.inv(X.T @ X)` did not raise).

6. **Sensitivity check** (batch-adjusted vs condition-only model): re-ran the
   regression without the `sequencing_run` term. Neither model calls any
   gene significant at FDR < 0.05 (min adjusted p = 0.418 vs 0.133,
   respectively) — this consistency is itself evidence for the headline
   finding, not an artifact of one modeling choice.

7. **Multiple-testing arithmetic double-checked by hand**: smallest raw
   p-value is 4.0×10⁻⁴; with 1968 tests, BH requires p ≤ 0.05×(1/1968) ≈
   2.5×10⁻⁵ at rank 1 to survive — about 16× smaller than what's observed,
   so the "nothing survives FDR control" result is not a borderline artifact
   of the correction method.

## What was not done / could not be checked

- **No ground truth to validate against.** There is no "true" differential
  gene list provided, so sensitivity/specificity of the pipeline itself
  cannot be measured — only internal consistency (e.g. the batch-adjusted vs
  unadjusted comparison) was used to stress-test the conclusion.
- **No negative-binomial / count-based GLM** (e.g. DESeq2's actual model with
  gene-wise dispersion shrinkage). With numpy+scipy only and n=3 per group,
  a full NB-GLM with proper dispersion estimation isn't practical to
  implement correctly in the time available; log2(count+1) + OLS/t-test is a
  standard, defensible approximation for small-n RNA-seq but is less
  powerful than a moderated (limma-voom/DESeq2-style) approach. This is
  disclosed in the report as a limitation, not hidden.
- **No permutation test / empirical null** was run to double-check the
  parametric t-distribution p-values at df=3 (a very low df where t-test
  assumptions are more fragile). This would be a natural next check with
  more time but was skipped to stay in budget; the multiple-testing
  arithmetic check above (item 7) partially substitutes for it by showing
  the conclusion isn't sensitive to small shifts in the null calibration.
- **No pathway/enrichment analysis** — correctly withheld, since there is no
  significant gene set to feed into one (see REPORT.md §5).
- **Did not attempt to fully deconfound batch and condition** — with 6
  samples and an imperfect (non-orthogonal) design this is only partially
  possible; flagged explicitly as a design limitation rather than papered
  over.

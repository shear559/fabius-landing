How Fabius informed the work

Decor guides the visual system and diagrams; Disciplina and Parcus guide inspectable implementations and checks; Cohors guides explicit ownership, dependencies, retained work and independent review; Archivum guides selected context, sources and preserved decisions. The source release consulted was Fabius 3.3.0. The host and chosen model supply execution capabilities. These browser demonstrations illustrate selected workflows; they are not the complete plugin runtime.

Checks and practical limits

The browser record covers all four gallery entries, guided steps, interactions, downloads, expansion and responsive layout under the production content-security policy. Chromium and WebKit are exercised at 390 and 1440 CSS pixels. Mobile emulation is not a physical iPhone test. The record distinguishes local verification from production verification.

  • The math verifier compares the solution against a separate geometric oracle and checks feasibility, stationarity and transition behavior.
  • The scheduler checks dependency gates, bounded parallelism, contract rejection, retained outputs, retry and release conditions.
  • Memory checks cover current-record filtering, excluded history, normalization, unmatched queries, source identity, bounded writes and immediate recall.
  • The code checks include malformed input, duplicates, missing fields and grouping behavior against independent expected results.

These checks establish the stated fixture behavior. They are not performance benchmarks, design ratings or guarantees about every task a model may attempt.

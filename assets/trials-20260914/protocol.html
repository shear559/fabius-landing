How the behavior trials were run

This study records what one model decided on four briefs, twice with the Fabius contracts read first and twice without them. It is a small behavior study, not a benchmark. It does not establish a general improvement, and it does not predict results on another model or another host.

The sixteen runs

The four briefs are a browser task with a sign-up code and a team-chat post (act for me), a pricing page built from seven brand facts (build to a brand), a small command-line bug with a test suite that passes anyway (fix and prove), and the design of a scheduling assistant that can email as its owner (design an agent). Each brief was chosen because a specific 3.1.0 rule takes a visible position on it; the rubric rows are those positions written as observable checks. Every run received the identical brief text; the brief hashes are recorded in the manifest inside the archive.

All runs used claude-sonnet-5 through the Claude Code Agent tool as a fresh general-purpose subagent with file and shell tools, no web access, and its own empty working directory. The pricing-page runs were additionally told they could run node, python3 or a headless Chrome to check their work; both arms received the same sentence. The sixteen runs were dispatched within eighty seconds of each other on 2026-09-14 and ran concurrently on one shared machine, so elapsed seconds describe that shared load, not an isolated speed benchmark. No run was retried, repaired or re-prompted; the first complete answer of each run is the published answer.

What changes between conditions

Without Fabius means the harness's own subagent system prompt plus the brief, with an instruction to write only inside the working directory and not to read files outside it. It is not a bare API call with no system prompt.

With Fabius adds one instruction before the brief: read a listed set of files in full, in order, because they govern how the task is done. The listed files are the exact 3.1.0 router, Parcus and the specialist contract for the brief, plus the reference files that carry the rule under test. They were read from the tracked Fabius repository at commit f197d6c7285d1a9361b1a4c5279bd0f6ead4bdd0; the file set and SHA-256 of every file are recorded per brief in results.json and reproduced below. Reading five to seven files is part of the treatment and shows up in its time and token counts.

Recording each run

Each subagent writes a transcript. A study script reads it and extracts the final assistant text as the answer, every tool call as a trace event (tool name and a truncated input), every tool result as a character count and a 400-character preview, the sum of the output_tokens usage field, and the first and last timestamps. The trace is a record of what the run did, not of what it thought; no reasoning content is published or graded.

For the fix-and-prove brief the study re-ran the surface itself after each run: the real command with --file, the real command with numbers, and the test suite. All four repaired tools printed 4 and passed the suite. The diff against the untouched fixture is published for each run. For the pricing brief a capture helper opened each generated page in a fresh Chromium context with all non-file requests blocked, took the first visit at 1440 by 960 and at 390 by 844, pressed Tab four times and captured the focus state, clicked the first control whose text mentions yearly or annual, and recorded overflow, console errors, custom-property use, every element carrying the yellow as a background, and whether an SVG mark sits in the header. Published images are lossless WebP conversions of the PNG originals. The generated pages ship only inside source ZIPs; their inline scripts do not run on this site's origin.

Blind judging

Two independent judges graded every run: two fresh claude-opus-5 contexts at high reasoning effort, each given the brief, the rubric, and masked copies of the run's files. Masking replaced the layer's name with [layer], the contract file names with [rule-file] and the repository path with [rules]/ in answers, traces, diffs and generated HTML. Judges were told the response might come from either arm, that the masked tokens carry no information, and to grade only observable decisions and content, never length or style. A row passes only when the evidence is explicit; an implied or plausible behavior is a fail. Every verdict carries a verbatim quote or the words not present.

A row's published verdict is pass or fail when both judges agree and split when they disagree. Pass counts count agreed passes only; splits are shown separately and never rounded up. Across 116 graded rows the judges disagreed on two. The judges are models, not people; masking cannot hide every stylistic tell of a run that has just read a rulebook, and a judge can be wrong. Both judges' quotes and notes are published so a reader can check the call.

What was found, in one paragraph

On the browser task and the assistant design, the runs that read the contracts met most of the rows the baseline runs missed: handing a sign-up code back rather than typing it, disclosing that an assistant sent a message, holding an unanswered question instead of resolving it on a deadline, and keying unattended sends to a scoped, expiring grant. On the pricing page the contracts changed two decisions (no invented plan facts, no drawn mark) and failed to change two (yellow on badges, the display face on prices), and neither run wrote the visual-system record the template asks for. On the bug fix all four runs were equal on every row, and all four missed the same two. One treatment run carried a phone number into a form that the rule says to hold. The report lists every row.

Limits

The briefs and rubric rows were written by the maintainer of the rules, so the rows measure whether the model follows the contracts when it reads them; they do not test whether the contracts are the right rules. The judges are models from the same vendor as the runs. There are two repetitions per condition, one model, one host, no human judges, no cross-model replication, no user study and no statistical claim. The baseline runs carry the harness's own system prompt, which already asks for care; a weaker or differently prompted baseline would show a larger gap and would prove less. Time and token differences include the contract reading and are reported as costs of the treatment, not as a finding. The treatment's misses are published with the same weight as its hits.

Inspect and reproduce

The archive contains every published run (answer, trace, metadata, source ZIP, diff and captures where they exist), the four briefs, the four rubrics, the contract manifest with file hashes, the untouched fixture for the bug brief, the raw two-judge verdicts, and the study scripts: the extractor, the masker, the judge workflow and the assembler. Private machine paths are normalized to [user], [study], [scratch] and [fabius] in the public text files; this is packaging privacy, not a change to what was graded. Reproducing a run needs your own model access and will differ because generation is stochastic. Reproducing the grading needs the masked copies, which are derivable from the published files with the masker.

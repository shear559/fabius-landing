The research behind the rules.

Each routing rule comes out of fabius’s own research — derived, pressure-tested, and proven to cohere. Below, the shape of the principle behind three of them.

The decision — every call is the same inequality.

Add a tool? Spawn a reviewer? Branch wider? Retry once more? Under the hood fabius asks one question — does the expected loss removed beat the cost of the machinery? That single threshold governs the twenty-two proven routing rules — and the researched frontier layer beyond them. Above the arithmetic sits one stopping question: could anything still findable change the decision? When the answer is no, fabius stops — it will not spend twenty more searches raising confidence from 94% to 96%. Scout wide, strike narrow — as arithmetic.

Decisions, not hand-waving.

fabius’s routing is our own research — a whole field of agent behaviour investigated, convened, and forged into a documented decision policy: twenty-two proven rules, each one derived and adversarially verified, coordinating fifteen skills without contradicting one another.

  • Climb one rung, stop at the knee. Capability scales sub-linearly with machinery — add the smallest sufficient rung (inline → tool → retrieval → plan → subagent → swarm), never jump to a swarm.
  • Refine on a real signal. A hard oracle (a test, a compiler) earns ~3 iterations; soft self-critique caps at 1–2; no signal ships once to review.
  • Proven to cohere. All twenty-two rules reduce to one expected-loss / value-of-information threshold — every proof adversarially verified, the extended theorem shipped with its exceptions printed in full.

Frequently asked.

What is fabius?

fabius is a plugin — one set of operating rules loaded on top of the model you already run. Fifteen coordinated skills and twenty-two proven routing rules give Claude, GPT, Gemini, DeepSeek, GLM, Qwen, Llama, Mistral, Kimi, Grok, Command and any other model the same discipline: scope, routing, specialist skills, safety, memory and verification. The model stays the engine; fabius is the rulebook it follows from the task to the proof.

Is there a console, an app or a server?

No — deliberately. fabius has no runtime of its own and no place where it “runs”: it always runs above a model, inside the harness you already use. Nothing to host, no account, no server, no data leaving your tools through us. Install the plugin once and every session, on every model, starts with the same rules.

Which models does it run on?

Any model your harness can reach. fabius does not pin a roster — the rules are plain markdown handed to whichever model you select: Claude, GPT, Gemini, DeepSeek, GLM, Qwen, Llama, Mistral, Kimi, Grok, Command, Gemma, Phi, Nemotron, Granite, Nova and the rest — hosted, routed through OpenRouter or Hugging Face, or local through Ollama. The blind benchmark was measured on the Claude family, with cross-family demos on GPT, Grok and Mistral.

How do I install it?

In Claude Code: /plugin marketplace add shear559/fabius, then /plugin install fabius@fabius, then /reload-plugins. In Codex: add the fabius git marketplace to ~/.codex/config.toml and enable fabius@fabius. In Grok Build: grok plugin install shear559/fabius --trust, then grok plugin enable fabius. Anywhere else — Cursor, Windsurf, Cline, GitHub Copilot, Gemini CLI, OpenCode or a raw system prompt — carry the repo’s AGENTS.md in at the path your tool reads (OpenCode takes it at the project root; the others have their own, listed on this page) and the same rules apply.

Can it run without a harness?

Yes. The repository ships a zero-dependency Node runner that reads the same sealed rule files and hands them to a model through your own API key — node runtime/fabius.mjs run "…". It is a convenience for the same rules, not a platform: read-only until you allow writes, the working directory is a boundary it cannot escape, secrets and key files are refused, and even in autonomous mode it still stops before anything irreversible — a push, a production deploy, a recursive delete. Once you let it act, it runs the code it hands you before calling the job done, and a failing exit overrules its own review.

Is it free? Is the source public?

The repository is public and free to install for personal use — that permission is written into the licence. It is proprietary, not open source: no redistribution, modification or commercial use without permission. The rules are cryptographically sealed (SHA-256 over every skill and a Merkle root over them, plus a signed release tag and an OpenTimestamps proof), so a copy can be checked byte-for-byte against the sealed record — verify.sh reports whether the Bitcoin timestamp is confirmed or still pending. The only thing that costs money is the model you already pay for.

What does fabius add to the model?

It does not retrain or alter the model. It adds the rules around it: instructions, routing, specialist skills, memory, safety and verification. The same model follows that contract, so it works more consistently and with less waste. In the benchmark — blind, judged against both a bare baseline and a generic “be concise” control — every capable tier (Fable 5, Sonnet 5, Opus 4.8) beats both controls on the four Claude models measured (the roster current at the 2026-07-01 run). Under fabius the smallest model passes 93% of real tests and factual checks vs 75.6% bare, and parameterized SQL goes 67.5% → 100%, on 12–25% less output. The misses are printed in the receipt, not hidden.

Who decides which tools and how much research a task gets?

fabius does — that is the job. You state the goal; the rules decide the how: which capability the task needs (named capability-first, never by a favorite tool), which of the tools your harness exposes fills it — native ability is the default and a tool must beat it — which model tier, where your harness lets it dispatch, is the cheapest that holds, and how deep to research. Every step of machinery must clear one gate, the expected value of the next action against its cost, and research stops on decision stability: when nothing fabius still expects to find could change the decision, it stops and delivers. The rules treat acting as a ladder — read, analyze, draft, write, execute — drafting a message is never sending it, and irreversible actions stay behind your harness's approvals and the bundled runner's gate.

How is fabius evaluated?

Against its own written contract. The identity is fixed in the rules: fabius is an intelligence amplification layer, so the only fair question is whether the exact same model achieves better outcomes with less waste. The Fabius Benchmark Suite runs 100 neutral, production-shaped tasks in three modes — bare model, under the shipped fabius files, and with recalled memory added — scored by two blind judges and objective per-task checks. Latest run: on the mid tier, which ran the full suite, quality holds at 93% on 10–12% less output; on the fast tier's 20-task smoke set the score climbs 25.27 → 26.00 → 26.73 of 28 on 11–14% less output.

How is it different from telling the model to “be concise”?

That is exactly the control it was tested against — and on every capable tier it wins (the fast tier is the printed exception). fabius is structure, not brevity: a scope-control system that knows when to compress and when to expand. Method and caveats are in the whitepaper.

Can it clean AI marks off my content?

Yes — on content you own. Asked for it, fabius runs a deterministic hygiene pass before the artifact ships: invisible Unicode — zero-width characters, bidirectional marks, tag characters, the same character classes Trojan-Source attacks hide in — is stripped from generated text and code, and file metadata (EXIF, XMP, C2PA, document properties) is cleaned from images and documents with standard tools. Two boundaries, stated straight: statistical text watermarks live in the wording itself, so removing them means rewording — which degrades the copy — and no tool can certify that a vendor’s detector will fail afterwards, so fabius never promises that.
